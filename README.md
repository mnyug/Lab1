# Симулятор складских маршрутов

[![Tests](https://github.com/mnyug/Lab1/actions/workflows/tests.yml/badge.svg)](https://github.com/mnyug/Lab1/actions/workflows/tests.yml)

Библиотека на C# для моделирования движения грузовика, приёмки и отгрузки товаров между складами. Учебный проект по объектно-ориентированному программированию в ИТМО, оформленный как отдельный репозиторий.

## Возможности

- Маршрутный лист из последовательных этапов: движение, отгрузка и приёмка.
- Учёт товаров по SKU и количеству; ограничения по весу и объёму.
- Проверка остатков, вместимости и расстояния между грузовиком и складом перед перемещением товаров.
- Распределение груза между сотрудниками с учётом их переносимой нагрузки и нескольких подходов.
- Расчёт длительности маршрута и остановка при первой неуспешной операции.
- Отдельные типы результатов для нехватки товара, вместимости, сотрудников и недопустимого расстояния.

## Сборка и тесты

Требуется **.NET SDK 10.0**. Проект не зависит от других лабораторных.

```bash
git clone https://github.com/mnyug/Lab1.git
cd Lab1
dotnet build Project.slnx --configuration Release
dotnet test Project.slnx --configuration Release
```

Это библиотека; сценарии использования представлены в тестах. Исполняемого приложения и команды `dotnet run` нет.

## Устройство

- `src/Lab1/Entities` — грузовик, склад, товары, манифест и этапы маршрута.
- `src/Lab1/ValueObjects` — вес и объём, координаты, скорость, время и результаты операций.
- `src/Lab1/Interfaces` — контракты этапов маршрута и стратегии распределения груза.
- `src/Lab1/Services` — стратегия распределения груза между сотрудниками.
- `tests/Lab1.Tests` — xUnit-тесты вместимости, остатков, времени движения, распределения груза и остановки маршрута при ошибке.
- `docs/assignment.md` — исходное условие лабораторной.

## Границы модели

Координаты обрабатываются как точки на плоскости: евклидово расстояние интерпретируется в километрах. Географический расчёт по широте и долготе и построение дорожных маршрутов не реализованы.

В текущей реализации приёмка и отгрузка используют общий расчёт времени; исключение последнего переноса при приёмке из условия пока не реализовано. Стратегия распределения груза последовательная и не гарантирует оптимальное время.

Вместимость и остатки проверяются в сценариях этапов маршрута; низкоуровневые методы изменения запасов требуют предварительной проверки вызывающим кодом. Выполненные этапы не откатываются целиком при ошибке на последующем этапе.
